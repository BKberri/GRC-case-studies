# Threat Intelligence Report
## 2026-09-AWS-Bulletin-MCP-Server-InputValidation
**Date:** 2026-09-07 | **Source:** AWS Security Bulletins (published 2026-09-04) | **Severity:** High | **Category:** AI-Governance / Cloud-Security

## Executive Overview
AWS Labs maintains a family of open-source Model Context Protocol (MCP) servers that give AI agents (Claude, Amazon Q, custom LangChain/Bedrock agents, etc.) tool-calling access to AWS services like Postgres-compatible databases and DynamoDB. On 2026-09-04, AWS published two bulletins disclosing input-handling defects in two of these servers. In `postgres-mcp-server`, the SQL-validation component that is supposed to enforce a read-only mode for an agent session uses an incomplete denylist of disallowed SQL constructs, so a sufficiently crafted statement embedded in content the agent submits can modify data even though the operator configured the MCP session as read-only. In `dynamodb-mcp-server`, the CDK-code-generation feature — which turns a declarative DynamoDB data-model file into deployable AWS CDK infrastructure code — passes table, index, and attribute names into a template engine without neutralizing template-injection metacharacters, so an attacker who controls any of those names (for example, through a data-model file sourced from an untrusted repository or an agent that ingests untrusted schema input) can achieve arbitrary code execution when the generated CDK application is synthesized or deployed.

## Technical Details
- **CVE IDs:** CVE-2026-85787 (postgres-mcp-server); CVE-2026-85654 (dynamodb-mcp-server)
- **CVSS:** CVE-2026-85787 — High (no numeric AWS score published); CVE-2026-85654 — CVSS v4.0 7.1 (`AV:L/AC:L/AT:P/PR:N/UI:A/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N`), High
- **Affected Vendor/Product/Version:** `awslabs.postgres-mcp-server` (PyPI) all versions before 1.1.7, fixed in 1.1.7; `awslabs.dynamodb-mcp-server` versions 2.0.10 and earlier, fixed in 2.1.6
- **Vulnerability Type:** CVE-2026-85787 — incomplete input validation / denylist bypass (CWE-184, Incomplete List of Disallowed Inputs); CVE-2026-85654 — improper neutralization of special elements in a template engine (CWE-1336), leading to code injection in generated infrastructure-as-code
- **Exploitation Status:** No confirmed in-the-wild exploitation; both are vendor-disclosed hardening fixes, not KEV-listed
- **Threat Actor Attribution:** None — internal/responsible discovery, not attributed to an active campaign
- **MITRE ATLAS Techniques:** AML.T0051 (LLM Prompt Injection framing is adjacent but not the vector here — the more precise mapping is AML.T0053, LLM Plugin Compromise) for the trust-boundary failure between agent-issued intent and the privileged action the MCP tool executes; MITRE ATT&CK T1190 (Exploit Public-Facing Application) is applicable to the DynamoDB CDK generator once deployed as a service, and T1059 (Command and Scripting Interpreter) for the resulting code execution
- **IOCs:** For postgres-mcp-server, unexpected INSERT/UPDATE/DELETE/DDL statements executing against a database role or session configured for read-only agent access; for dynamodb-mcp-server, anomalous or unrecognized code blocks appearing in CDK-generated application output, or CDK synth/deploy failures on data-model files sourced from external or agent-populated input
- **CISA Remediation Due Date:** Not applicable — not KEV-listed; AWS bulletins recommend immediate upgrade as standard practice

## Affected Technology Context
Both servers exist specifically to let AI agents take actions against AWS data infrastructure using natural-language-derived intent instead of hand-written, reviewed code — the entire value proposition is delegating a privileged operation (a database query, an infrastructure deployment) to an agent loop that is, by design, driven by less-deterministic input than a traditional API caller. That is precisely why both defects matter beyond their individual CVSS scores: the postgres-mcp-server flaw defeats the specific safety mechanism (a read-only mode) an operator would reasonably configure to bound what an agent can do to a production database, and the dynamodb-mcp-server flaw turns a code-generation convenience feature into a code-execution primitive if any part of the input data model is attacker-influenced — a realistic scenario given how often data-model definitions are pulled from shared repositories, ticketing systems, or agent-ingested documentation rather than typed by a human reviewer. This is the second consecutive weekly sweep in which an AWS-published disclosure maps to the same underlying pattern flagged in the 2026-08-10 CoreBreak finding (RR-049): agentic AI tooling's trust boundary between "what the agent was told to do" and "what privileged operation the tool actually performs" is an emerging, cross-vendor architecture-class risk, not a one-off implementation bug.
