## Remediation Narrative
Patch all in-use instances of the four affected packages/services to their fixed versions: Google ADK for Python to 2.5.0 or later, Vercel @ai-sdk/harness-codex to 1.0.29 or later, @ai-sdk/harness-opencode to 1.0.28 or later. Amazon Bedrock AgentCore's managed InvokeHarness API is already fixed server-side with no customer action required; however, any organization running the open-source Strands Python SDK directly (outside the managed AgentCore service) should implement AWS's documented mitigation — building conversation/message history exclusively from trusted, application-controlled sources rather than caller-shaped input — since no code fix has been issued for that standalone path. Independent of the specific CVEs, conduct an architecture review of any internally-built agentic AI system for the same "trusts tool-call-shaped data without verifying model provenance" pattern.

## Compensating Controls
For any agent system (patched or custom-built) with access to sensitive tools (deployment, financial actions, data access), apply least-privilege scoping so each agent holds only the tools and credentials required for its specific task, limiting blast radius if an authorization-bypass flaw is later found. Treat conversation history, resumable session events, and confirmation/approval responses as untrusted input whenever they cross an external system boundary.

## Verification & Closure Criteria
Closure requires: (1) confirmed patched versions in use for all instances of the four affected packages; (2) documented mitigation applied for any standalone Strands SDK deployments; (3) completed architecture review of all in-house agentic AI systems against the CoreBreak pattern, with findings remediated or formally risk-accepted; (4) updated AI system design-review checklist published and communicated to engineering teams building agentic AI systems.
